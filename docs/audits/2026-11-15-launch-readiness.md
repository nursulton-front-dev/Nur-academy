## 2. Что подтверждено реальными тестами в изолированном окружении

Все проверки выполнены на физическом локальном кластере PostgreSQL 16 (порт 5433, база `nur_test_db`), а не на in-memory моках:

1. **Тестовый набор `scripts/test-real-postgres-acceptance.mjs`** (21 тест — ВСЕ ПРОЙДЕНЫ):
   - **8 тестов целостности попыток**:
     * Отклонение диагностической попытки с 1 вопросом триггером БД (`must contain exactly 50 assigned question IDs`).
     * Отклонение попытки с дублирующимися ID вопросов.
     * Отклонение попытки с вопросами из другого курса (Tarix -> Informatika).
     * Автоматический сброс поддельных `total_score` и `finished_at` в `NULL` триггером `BEFORE INSERT`.
     * Запрет прямого `UPDATE` на `diagnostic_attempts` от роли `authenticated` (HTTP/SQL 42501).
     * Запрет межпользовательского изменения попыток.
     * Отклонение экзаменационной попытки с произвольным числом вопросов (разрешены строго 20 или 50).
     * Запрет прямого `UPDATE` на `exam_attempts` от роли `authenticated`.
   - **7 тестов реальных прав доступа**:
     * `anon`: ошибка доступа `permission denied for column is_correct on answers`.
     * `authenticated`: ошибка доступа `permission denied for column is_correct on answers`.
     * `answers_public`: безопасное представление возвращает только `(id, question_id)`, колонка `is_correct` отсутствует.
     * `anon`: доступ к `question_keys` запрещён (0 строк / RLS).
     * `authenticated` (студент): доступ к `question_keys` запрещён (0 строк / RLS).
     * `question_bank_translations`: ровно 0 опций содержат `is_correct` в базе данных.
     * `question_bank_translations_public`: представление возвращает очищенный JSON опций без `is_correct`.
   - **6 тестов транзакционной конкурентности**:
     * Две одновременные отправки `check-answer` с противоположными ответами на одну диагностическую попытку: ровно один запрос фиксирует оценку в БД, второй получает `already_completed: true` с идентичным баллом.
     * В базе данных сохраняется результат выигравшего запроса с непустым `finished_at`.
     * Повторный запрос к завершённой диагностике возвращает `already_completed: true` без побочных эффектов.
     * Две одновременные отправки экзаменационных ответов: атомарное завершение, проигравший получает `already_completed: true`.
     * Повторный запрос к завершённому экзамену возвращает `already_completed: true` с сохранением исходного балла.
     * Параллельный вызов `finish-exam` на mock-экзамене: атомарная фиксация без дублирования начисления баллов.

2. **Тестовый набор `scripts/test-browser-free-scenario.mjs`** (10 тестов — ВСЕ ПРОЙДЕНЫ):

## 3. Подтверждённые и устранённые уязвимости

1. **Подмена вопросов и прямой взлом оценок в попытках**:
   - *Уязвимость*: Пользователь с валидным JWT мог через REST API выполнить `POST /rest/v1/diagnostic_attempts` с массивом из одного лёгкого вопроса, либо отправить `PATCH /rest/v1/diagnostic_attempts?id=eq.<id>` и напрямую записать `total_score = 100`, `finished_at = now()`.
   - *Устранение*: В миграции `20261116130000_secure_attempts_and_views.sql` отозваны права `UPDATE` и `DELETE` у ролей `anon` и `authenticated`. Добавлены триггеры `BEFORE INSERT`, принудительно устанавливающие `total_score = NULL`, `finished_at = NULL` и проверяющие принадлежность и количество (50 для диагностики, 20 или 50 для экзамена) вопросов курсу со статусом `published`.

2. **Окно утечки ключей ответов до завершающей миграции**:
   - *Уязвимость*: При разделении миграций на А (копирование в `question_keys`) и Б (удаление из `question_bank_translations.options`) ключи оставались публично доступны в таблице переводов.
   - *Устранение*: Создано безопасное представление `question_bank_translations_public`, исключающее `is_correct` на уровне SQL. Регламент релиза изменён: Миграция Б применяется в рамках единого окна технического обслуживания сразу после верификации Миграции А, устраняя промежуточное окно утечки.

3. **Утечка правильных ответов к тестам уроков**:
   - *Уязвимость*: Таблица `public.answers` имела `select using (true)`, позволяя читать `is_correct` напрямую.
   - *Устранение*: В миграции `20261116120000_attempt_question_ids.sql` отозван прямой `SELECT` на колонку `is_correct` у ролей `anon` и `authenticated` и создано безопасное представление `public.answers_public (id, question_id)`.

4. **Ложные маркетинговые обещания**:
   - *Уязвимость*: Тексты тарифов и лендинга обещали выдачу сертификатов, в то время как бэкенд их генерации отсутствует.
   - *Устранение*: Все упоминания выдачи сертификатов удалены из маркетинговых материалов, страница `/certificates` информирует о подготовке функционала после завершения бета-тестирования.

## 4. Сквозная проверка параллельности и браузерного пути

- **Параллельность (Real PostgreSQL ACID)**:
  Предикат `.is('finished_at', null)` в связке с атомарным `UPDATE ... RETURNING` в Edge Functions гарантирует, что при одновременной отправке двух противоречивых запросов ровно один обновляет строку в дисковой таблице PostgreSQL. Второй запрос фиксирует `0` затронутых строк и возвращает клиенту ранее зафиксированный результат без повторного начисления XP или изменения статистики.
- **Браузерный сценарий (Headless Chrome)**:
  Подтверждена стабильная работа интерфейса: начальный экран диагностики корректно загружает состав теста, блоки уроков последовательно открываются, платные AI-функции наглухо закрыты кодом 403 на сервере, завершение сессии сбрасывает локальные ключи и корректно перенаправляет на экран входа.

## 5. Точный список действий для безопасного релиза

Выполнять строго в указанном порядке при публикации:

1. **Создание резервной копии production БД**:
   ```bash
   supabase db dump -f backup_pre_launch.sql
   ```
2. **Применение миграций БД (в рамках одного окна обслуживания)**:
   ```bash
   supabase db push
   # Применяются миграции:
   # 1. 20261115100000_stage0_question_keys_non_destructive.sql (создание question_keys)
   # 2. 20261115200000_stage0_strip_answers_destructive.sql (очистка options, 0 leaked keys)
   # 3. 20261116120000_attempt_question_ids.sql (привязка question_ids, answers_public)
   # 4. 20261116130000_secure_attempts_and_views.sql (триггеры целостности, отзыв UPDATE)
   ```
3. **Автоматическая верификация базы данных после миграций**:
   ```sql
   -- Должно вернуть 0:
   SELECT count(*) FROM public.question_bank_translations, jsonb_array_elements(options) opt WHERE opt ? 'is_correct';
   -- Должно вернуть число вопросов:
   SELECT count(*) FROM public.question_keys;
   ```
4. **Развёртывание Edge Functions**:
   ```bash
   supabase functions deploy check-answer
   supabase functions deploy finish-exam
   supabase functions deploy get-exam-questions
   supabase functions deploy explain-mistake
   supabase functions deploy daily-recommendation
   ```
5. **Сборка и развёртывание фронтенда**:
   ```bash
   npm run build
   # Публикация артефактов из dist/
   ```
6. **Финальная smoke-проверка на production**:
   - Пройти диагностический тест от тестового аккаунта.
   - Убедиться в получении HTTP 403 при вызове `explain-mistake` без подписки Pro.
